#Robots for simulation and motion planning

Generates and checks robot descriptions (URDF for ROS, MJCF for MuJoCo, SRDF for MoveIt) from a cad model with joints, and checks hand-written ones. Use to export a robot or mechanism for simulation or motion planning, or to validate a .urdf, .srdf or MJCF .xml. Not for the CAD part itself, which the cad skill makes, and it runs no simulation.

A robot is described for its consumers in XML: a URDF for its structure (ROS, RViz, robot_state_publisher), an SRDF beside it for MoveIt's planning semantics, and an MJCF for MuJoCo. With a cad model the model is the source of truth and the files are exports: regenerated, never edited. docs/robots.md in the repository is the full contract.

#Generate from the model

The model says what is true of the machine (the cad skill covers joints, poses and couplings):

In the modelWritten as
revolute, prismatic, fixed joints in an assemblyLinks and joints (bodies with hinges and slides)
limits on a joint<limit> / range, as offsets from the as-built pose, which is zero
couple(...)<mimic> / <equality><joint polycoef>
posesMJCF <key>s and SRDF <group_state>s
material on each part (density)Exact <inertial>s: mass, centre of mass, tensor
colours<material> / rgba
cad run src/arm.ts                                   # prints the id
cad model ranges "$ID"                               # stops from the geometry
cad model export "$ID" description/arm.urdf description/arm.srdf sim/arm.xml
cad model export "$ID" arm_description/urdf/arm.urdf --package arm_description   # package:// meshes for ROS

The suffix picks the format: .urdf, .srdf, .xml or .mjcf (MuJoCo). Meshes are written beside the file (meshes/ for a URDF, assets/ for an MJCF), one binary STL per part, in metres in its link's frame. An MJCF export also writes a scene.xml (the robot, a floor, a light) once, never over yours. Unchanged files are not rewritten.

Each export prints what it wrote (robot 'arm', root 'base_link', 5 links, 4 joints (3 movable), … total mass 1.2 kg) and warns on stderr of what it could not know. Read both:

  • A part with no material weighs nothing. A moving link without mass is refused by a

    simulator: give every part a material and export again.

  • Effort and velocity are written 0 unless the joint declares them (`revolute("elbow", { …,

    effort: 2000, velocity: 180 }): N·mm or N, deg/s or mm/s, written to URDF as N·m and rad/s and to MJCF as actuatorfrcrange). ROS controllers read 0 as none allowed; cad urdf validate warns zero_effort/zero_velocity` for a joint without them.

  • A slide without limits is written ± the model's extent: declare its stops.

What the export does:

  • Link frames keep the document's axes; a joint's child link frame sits on its axis origin as

    built, so every rpy is 0 and each <axis> is the joint's declared direction.

  • The root link is base (the parts no joint moves), hung from an empty base_link.
  • Units are SI: metres, kilograms, radians. A snapshot's --pose takes degrees and mm.

Never edit a generated file. A frame, limit, mass or mesh is changed in the model and exported again. A collision shape, damping or actuator for MuJoCo goes in your scene.xml or a file that includes the robot's.

#Check each change

cad urdf validate description/arm.urdf
cad urdf validate arm_description/urdf/arm.urdf --packages arm_description=arm_description
cad srdf validate description/arm.srdf --strict
cad mujoco check sim/scene.xml --json

Each prints one line per finding (warning: zero_effort at /robot/joint[@name='yaw']/limit: … Hint: …), then OK file: summary or FAILED file: …. Exit 0 passes; 1 fails (an error, or a warning with --strict); 2 is a refused command (no such file). --json prints the report as one object.

  • URDF: one root, unique names, joints between links, types, axes, limits, mimics, one shape per

    visual and collision, mesh files on disk, a positive mass and a positive semidefinite inertia are errors; an omitted or non-unit axis, missing or zero effort and velocity, limits a consumer ignores, a link and joint of one name, a moving link without an inertial, inertias breaking the triangle inequality, an unresolved package:// mesh, unknown tags and undefined materials are warnings.

  • SRDF: pairs with exactly one URDF of the same robot name in its folder; every group, chain,

    state, end effector and disabled pair is checked against that URDF's names and limits.

  • MJCF: names, meshes on disk (STL, OBJ or MSH), masses and inertias of moving bodies, ranges,

    the angle unit and keyframe sizes; and MuJoCo's own compile where python3 -c "import mujoco" works (mujoco_compiled, else mujoco_skipped is printed).

Read the OK line as a check of its own: a wrong root, a count of movable joints that is off, or a total mass that is not the robot's is a fault no finding reports.

A clean check is not proof. It cannot tell that an axis or a sign is the robot's: move each joint through its limits (cad model snapshot ID j.png --pose shoulder=90) and look. Report which checks ran, which were skipped (MuJoCo, ROS's check_urdf), and what you assumed.

#Author by hand

For a robot with no cad model, or an SRDF beyond the generated one (end effectors, more groups): keep the units SI, copy every link and joint name from the URDF, put a comment at the top saying where each frame, axis, limit and mass came from, and run the checks above after every edit.

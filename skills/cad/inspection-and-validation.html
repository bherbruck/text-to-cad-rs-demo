#Inspecting and checking models

Read this file when resolving a reference, measuring a model, checking clearances or overlap, or diagnosing a failed or wrong build. Which check a change calls for is Check each change; this file is what the checks are made of.

The SDK builds no geometry in the script, so every number comes from the server: the summary a run prints, cad model inspect, or the handle a model call returns.

#The build summary

built src/bracket.ts::bracket in 0.41s: 14 ops, 9 hits, 5 misses
  parts 1 · bounds 40 × 30 × 35 mm · volume 11872.6 mm³ · mass 32.1 g
  warning: …
  id: 0dc50a92-…
  view: http://127.0.0.1:7878/view/0dc50a92-…?token=…
  • bounds is the overall size, X × Y × Z: the first check of any dimension the person gave.
  • volume is the sum over parts; a hole that didn't cut shows as a volume that didn't drop.
  • parts is the number of labelled parts (one for a single solid).
  • warnings are the server's: read them; an invalid solid or a part that isn't one solid shows

    up here first.

#References

A reference names a document, a part in it, or one face or edge of a part. It is what the viewer copies when the person picks something:

0dc50a92-a21f-5895-a245-ebdeb5352f3b                     the document
0dc50a92-…#bracket                                       a part, by its path of labels
0dc50a92-…#enclosure/lid                                 a part inside an assembly
0dc50a92-…#enclosure/lid/face 4                          a face of it (0-based, kernel order)
0dc50a92-…#bracket/edge 11                               an edge
  • A part's path is the labels from the root joined by /; in a document of one part it is that

    part's label. cad model inspect "$ID" takes the whole reference or just the part after # ('bracket/face 4'), as does a handle's inspect(...).

  • Face and edge numbers are the kernel's order for the shape as last built; an edit that changes

    the topology renumbers them. Resolve a reference against the current build, then select the element in code by what it is (selectors), not by its number.

#Inspect

cad model inspect "$ID"                            # parts, bounds, volume, mass, parameters
cad model inspect "$ID" "$ID#bracket/face 4"        # one face, with made_by (JSON)
cad model inspect "$ID" "$ID#enclosure/lid/edge 11"   # the id, '#', then the reference

With no ref it prints the document: each part's path, label, colour, material, kind (solid, compound, shell, …), volume, area, mass, centre, bounds, face and edge counts and valid.

With a ref it returns the part, and for a face: surface (plane, cylinder, …), area, center, normal, axis and radius where they apply, bounds; for an edge: curve (line, circle, …), length, start, end, mid, direction for a line, center, radius and normal for a circle, closed, bounds. These are exact (from the B-rep), not mesh estimates.

#Which code made it

made_by lists the ops in a part's history, newest first, each with the source line that created it:

"made_by": [
  { "op": "part", "src": "src/bracket.ts:26" },
  { "op": "cut", "src": "src/bracket.ts:25" },
  { "op": "fillet", "src": "src/bracket.ts:19" },
  { "op": "fuse", "src": "src/bracket.ts:17" },
  { "op": "box", "src": "src/bracket.ts:13" }
]

To act on a reference ("make this hole bigger"), resolve it, read the face's type and radius, find the op in made_by that made a feature of that kind and size, and edit that line.

#Checks in a script

A check calls the model, then measures what the handle returns. Keep it beside the model, or in a checks/ folder when it is worth keeping:

// checks/bracket.check.ts
import assert from "node:assert/strict";
import { bracket } from "../src/bracket.ts";

const h = await bracket();
const [min, max] = [h.result.bounds!.min, h.result.bounds!.max];
assert.ok(Math.abs(max[0] - min[0] - 40) < 1e-6, `width ${max[0] - min[0]}`);

const doc = await h.inspect();
assert.equal(doc.parts.length, 1);
assert.ok(doc.parts.every((p) => p.valid), "invalid solid");

const bore = await h.inspect("bracket/face 9");
assert.equal(bore.face?.surface, "cylinder");
assert.ok(Math.abs(bore.face!.radius! - 2.75) < 1e-6, `bore radius ${bore.face!.radius}`);
cad run checks/bracket.check.ts
  • A failed assert exits 1 with the message: the check failed. A check that could not run (a

    build error, a missing face) has shown nothing.

  • Trust a check only once you have seen it fail on a planted fault of the kind it guards against

    (set the width to 41 and run it).

  • A wall or clearance is a distance between two faces: inspect both and compare their centres

    along the normal, or take it from the parameters that made them and check the bounds agree.

#Interference

cad model interference "$ID"      # exit 1 if any pair of parts shares volume

It prints each pair of parts (by path) that overlap and the shared volume; await h.interference() returns the same pairs. Parts that only touch don't count. Run it on every assembly after placing parts, and say in the hand-off which states (lid open or closed) were checked.

#Models

#A model is a function

import { box, model } from "@cad/sdk";

export const plate = model("plate", () => box(60, 40, 3).label("plate"));

if (import.meta.main) await plate();
  • model(name, fn) declares; only a call builds. Importing a script builds nothing, so its

    if (import.meta.main) block chooses, in plain TypeScript, which models a run builds (a loop, process.argv, a condition). cad run SCRIPT.ts ARGS… passes the arguments through.

  • The name is an identifier (bracket, bracket_wide, lid-v2), unique within its script.

    The file that calls model() is the model's script.

  • The function returns a shape, a part or an assembly. It may be async.
  • The handle await m() returns has id, url, name, result (the server's build result:

    parts, bounds, cache, ms, warnings) and the commands inspect(ref?), export(...files), snapshot(out, opts), interference().

  • m.id is known without building; await m.ir() returns the op graph that would be sent,

    without contacting the server (useful to see what a selector parsed to).

  • The SDK computes no geometry. A shape in the script is a description; it has no bounds,

    volume or faces until the server builds it. Decide sizes from your own numbers (parameters, constants) and read measurements from the build (inspection).

#Parameters

A number a person will tune is declared with param and the code goes on with the plain number it returns:

export const box1 = model("tray", () => {
  const wall = param("wall", 2, { min: 1, max: 5, step: 0.5, unit: "mm" });
  const slots = param("slots", 4, { min: 1, max: 10, step: 1 });
  const depth = param("depth", 25, { min: 10, max: 60, unit: "mm", description: "inside depth" });
  return tray(wall, slots, depth);
});
  • Inside a model function, a parameter belongs to that model. At a script's top level it belongs

    to every model the script builds.

  • Options are min, max, step (> 0), unit (mm, deg, % or count) and

    description; anything else, a default outside min..max, or a name declared twice in one model fails the run with the parameter's name and line.

  • cad model inspect "$ID" lists them. To change a value, edit its default in the script and run

    it again. CAD_PARAMS='{"wall":3}' cad run src/tray.ts overrides values for one run.

  • Keep a parameter's default a plain number literal in the call, so a person (or the viewer) can

    find and change it.

#Assemblies

An assembly is a labelled tree of parts. Write each part as a helper that returns a labelled part, use it in the part's own model (to export or print alone) and in the assembly's:

// src/enclosure.ts
import { assembly, box, model } from "@cad/sdk";

const W = 90, D = 60, H = 32;

function base() { return box(W, D, H, { align: ["center", "center", "min"] }).shell(">Z", -2).label("base"); }
function lid() { return box(W, D, 3, { align: ["center", "center", "min"] }).label("lid", { color: "#d8dde3" }); }

export const enclosureBase = model("enclosure_base", base);
export const enclosureLid = model("enclosure_lid", lid);
export const enclosure = model("enclosure", () =>
  assembly("enclosure", [base(), lid().translate(0, 0, H)]));

if (import.meta.main) { await enclosureBase(); await enclosureLid(); await enclosure(); }
  • Moving a part keeps its label, colour and material; so does moving an assembly. A boolean

    or feature on a part returns a plain shape, so label after them.

  • Every part of an assembly gets a label. Its path, labels from the root joined by /

    (enclosure/lid), is how inspection, references, --part and exports name it. A plain shape put in an assembly is labelled <assembly>_<n>: label it yourself.

  • Assemblies nest: an assembly is a valid child of another, and moves as one.
  • Helpers from another script are imported like any TypeScript (`import { lid } from

    "./lid.ts"`). A model imported from another script is a separate document; its helper, called in this model, is part of this one.

  • The parts are separate solids: cad model interference "$ID" finds the ones that overlap.

#What a run runs

A run executes the script, which builds the op graph in memory and posts it (POST /api/build). The server hashes every node by its op, its arguments and its inputs' hashes, and reuses any node it has built before, in this model or any other. The first line of the summary counts them: 12 ops, 9 hits, 3 misses.

  • An edit recomputes what is downstream of it. Changing a fillet radius reuses the solid

    under it; changing the first box rebuilds everything above it.

  • Nothing to mark. There is no memo decorator: a helper called twice with the same arguments

    makes equal nodes, and the server builds them once.

  • Shared nodes are sent once. A shape reused in several places (a hole in a pattern, a part

    in two assemblies) is one node with several users.

  • A script is plain code. Loops, conditions, arrays and functions are all fine; randomness or

    the clock make a different graph each run, which just builds as new.

#Inputs

const motor = importStep("../vendor/motor.step").label("motor");   // relative to this script's folder
const scan = importStl("scans/pcb.stl");
  • importStep(path) brings a STEP file's geometry into the model as a shape (a compound for a

    multi-body file). Label it, move it, cut with it like any shape.

  • importStl(path) brings a mesh in as a shape of triangles: fine to place, show and check

    for interference; booleans and fillets on a mesh are slow or fail.

  • Paths are relative to the script's folder, or absolute. The file is read by the server when the

    node is built; its bytes are not part of the node's hash, so after replacing a file, change anything about the import (or restart the server) to re-read it.

#Documents and ids

  • The id names the model, not a state of it. It is a UUIDv5 of the script's absolute path and

    the model's name, so it is stable across runs, and a renamed model or a moved script is a new document.

  • A document keeps its last good geometry. A failed build records the error on the document

    (the page shows it) and leaves the last successful result in place.

  • cad model list lists every document; cad viewer FILE opens a STEP or STL as a document of

    its own (its id from the file's path).

#Errors

  • A bad argument fails in the script, before anything is sent: `CadError: box x must be > 0,

    got 0 (at src/plate.ts:12)`. Fix the line it names.

  • A failed build prints error: <message>, the op, and at src/plate.ts:14: the line that

    made the failing node. The run exits 1. The usual causes: a fillet or chamfer radius too large for its edges, a selector that matched nothing, a boolean between shapes that only touch, a shell thicker than the part allows.

  • No server: the run says so and how to start one (cad server start); cad run starts it

    for you.

#Circuit boards

Designs, checks and exports circuit boards and schematics as native KiCad files (.kicad_sch, .kicad_pcb, .kicad_pro). Use for any request about a PCB, a schematic or a circuit - choosing parts from KiCad's libraries, nets, placement and routing, ERC and DRC, a review before ordering, fabrication files (gerbers, drill, pick-and-place, BOM, PDF), a netlist, or a STEP of the board for an enclosure. Not for the enclosure or other mechanical parts, which the cad skill makes.

A board is its native KiCad files: the schematic, the board and the project. cad reads and inspects them itself, and runs KiCad's own kicad-cli for whatever KiCad owns: ERC, DRC, fabrication outputs and the board's STEP. A new design is written with @cad/sdk's pcb module: parts from KiCad's libraries, nets, an outline drawn as any cad profile, placement, tracks, vias and pours. Rewriting the script and running it again writes the files again.

#Setup

Run cad --version before first use in a chat. Inspecting a board or a schematic needs nothing else. ERC, DRC, exports, the STEP and writing a design need KiCad 9 or newer installed: its kicad-cli on PATH (or named by CAD_KICAD_CLI) and its libraries (/usr/share/kicad, or KICAD_SHARE). If they are missing, say so and say what to install; do not try to work without them.

kicad-cli runs headless with a private configuration ($CAD_HOME/kicad) holding KiCad's stock library tables, never the person's own KiCad settings. A project that carries its own libraries still finds them.

#Write a design

import { importStep, model, pcb, rect } from "@cad/sdk";

const d = pcb.design("divider", { title: "Voltage divider" });
const r1 = d.part("R1", { symbol: "Device:R", footprint: "Resistor_SMD:R_0805_2012Metric", value: "10k", at: [-3, 0] });
const r2 = d.part("R2", { symbol: "Device:R", footprint: "Resistor_SMD:R_0805_2012Metric", value: "4k7", at: [3, 0], rotation: 90 });
d.net("IN", r1.pin(1));
d.net("MID", r1.pin(2), r2.pin(1));
d.net("GND", r2.pin(2));
d.outline(rect(20, 10, { radius: 1 }));                  // any fresh cad profile; its holes are cut-outs
d.track("MID", [[-2.09, 0], [3, 0], [3, -0.91]], { width: 0.3 });
d.zone("GND", { layer: "B.Cu" });

const files = await d.write("hw/divider", { fill: true }); // .kicad_sch, .kicad_pcb, .kicad_pro
const drc = await pcb.drc(files.board, { parity: true });
const stepFile = await pcb.step(files.board);
await model("divider_board", () => importStep(stepFile))(); // the board and its parts, in the viewer
  • Parts come from KiCad's libraries by lib_id: symbol names the schematic symbol

    (Device:R, Timer:NE555D, Connector:USB_C_Receptacle_PowerOnly_6P) and footprint names the land pattern (Package_SO:SOIC-8_3.9x4.9mm_P1.27mm). Check that a name exists in the installed libraries (ls /usr/share/kicad/symbols, grep '(symbol "NE555' .../Timer.kicad_sym, ls .../footprints/Package_SO.pretty). Pin numbers come from the symbol, and the footprint's pads must use the same numbers. A pin with no pad is listed in the write's notes.

  • Nets join pins written REF.PIN ("U1.8", or u1.pin(8)). Each joined pin gets a label in

    the schematic, and each pin left free gets a no-connect flag. A power input that nothing drives gets a PWR_FLAG, so ERC passes on a clean design.

  • Board coordinates are millimetres with y up, from the outline's centre, as in cad's

    sketches. Rotation is degrees counter-clockwise. The written board is in KiCad's frame (y down, centred on an A4 page), and that is what inspect, DRC and the pick-and-place file report.

  • Routing: d.autoroute() routes everything the design leaves unrouted (below).

    Tracks you give with track(net, points, { width, layer }) and via(net, at) are kept, and the router works round them. Pours are zone(net, { layer }); fill: true has KiCad fill them. A track's points can be pins, which stand for their pads' centres: d.track("SDA", [u1.pin(3), [3.3, 3.4], r2.pin(2)]). write() returns every pad's centre in the design's frame (files.pads["U1.3"], mm, y up), to route by hand after a first write. A track ends where it touches a pad or another track of its net.

  • Two frames: the design is mm with y up from the outline's centre. The written board, and

    everything KiCad reports from it (cad pcb inspect, DRC's at, the pick-and-place file), is in KiCad's frame: y down, the outline's box centred at (148.5, 105) on an A4 page. For an outline centred on the origin (as rect draws it), convert with x = X - 148.5, y = 105 - Y; or use files.pads.

  • Sides and layers: side: "bottom" puts a part on the back, mirrored as KiCad mirrors it.

    rotation is still as seen from the top. stackup({ layers: 4 }) adds In1.Cu and In2.Cu, for planes: zone("GND", { layer: "In1.Cu" }).

  • Everything is written again on each run: the schematic, the board and the project. A design is

    the source; edits made in KiCad's app are lost at the next run, so make them in the script.

examples/blinky_pcb.ts is a complete design to start from: a 555 LED blinker powered from USB-C, routed by hand, with GND poured on both layers, passing ERC and DRC. examples/esp32_pcb.ts is denser and autorouted: an ESP32-C3 breakout on four layers with GND and 3V3 planes.

#Routing

The autorouter routes the outer copper layers (F.Cu and B.Cu) on a 0.1 mm grid: octolinear tracks, through vias, and every clearance measured to the true shapes. It routes round everything already there (pads, tracks, vias, keep-out rule areas, the board edge) and moves nothing. The same board always gives the same copper.

cad pcb route board.kicad_pcb                     # in place; --out other.kicad_pcb to keep the original
cad pcb route board.kicad_pcb --nets SDA,SCL --width 0.25 --clearance 0.2
  • Defaults: tracks 0.2 mm with 0.2 mm clearance, 0.5 mm from the edge. Power nets (GND, VCC,

    VDD, VBUS, +5V, 3V3...) are 0.4 mm wide where they fit. Vias are 0.6/0.3 mm. The options are width, power_width, clearance, edge_clearance, via_size, via_drill, pitch, via_cost, passes, nets and skip.

  • Order: nets are routed shortest first. Nets that fail are moved to the front and everything

    is routed again, up to passes times.

  • Pours and planes: a net with a pour is not tracked. Each of its pads on a layer the pour does

    not cover gets a short fan-out to a via. That is how pads reach an inner plane, or the other side's pour.

  • After routing, cad pcb route refills the pours and runs KiCad's DRC. The exit code is 0 only

    when every connection was made and DRC passed.

  • What it cannot route is named, net and pad: NOT routed: CC1 at J1.A5: ..., either no room

    at the pad or no way through. Make room (move parts apart, use a smaller footprint), or route that net by hand with track. Never loosen the clearance below the fab's minimum to make a route fit.

  • It does not route differential pairs as pairs (USB D+/D- are routed as two nets), match

    lengths, route inner signal layers, or place parts.

  • Check the result as you would any routing: DRC, then look at the copper

    (cad pcb export board.kicad_pcb pdf, or KiCad's own render, kicad-cli pcb render).

#Check each change

AfterRunClean means
A schematic changecad pcb erc FILEERC passed
A board changecad pcb drc FILE --parityDRC passed: no errors, and no unconnected items (each one is routing still to do)
Placement or routingcad pcb step FILE, then cad model snapshot <id> out.pngparts where intended, nothing off the board
  • The exit code is 0 when the check passes (warnings allowed), 1 when it found errors, and 3 when

    it could not run.

  • --json gives each finding as { rule, severity, refs, message, at, items }. refs names the

    parts (U1), pads (U1.3) or copper (#track:<uuid>). at is in the file's frame (KiCad's, y down).

  • Warnings count: silkscreen, mask and courtyard warnings are what a fab's CAM engineer flags.

    Fix the cause. A rule weakened to get a clean report has shown nothing.

  • A clean DRC means the board meets its own rules. It does not prove the circuit works, and it

    says nothing about the fab's limits. Pin functions, polarity and connector orientation come from the datasheet.

#Before ordering

Run ERC, then DRC with --parity. Every error blocks ordering unless the person says to go ahead; the report then names each error they went ahead with. Compare the board with the chosen fab's capabilities (JLCPCB's standard service if none is named, and say so): minimum track and gap, drill, annular ring, and board thickness. Then write only the deliverables asked for:

cad pcb export board.kicad_pcb gerbers drill pos bom --out fab/
OutputWrites
gerbersfab/gerbers/: copper, mask, paste, silkscreen and the outline, plus the job file
drillfab/drill/: Excellon drill files and a drill map
posfab/<name>-pos.csv: pick-and-place, both sides, mm
bomfab/<name>-bom.csv: grouped by value and footprint, from the schematic
pdf, sch-pdf, svgplots of the board and of the schematic
stepfab/<name>.step: the board and its parts' 3D models, centred on the outline
netlistfab/<name>.net: KiCad's netlist

#Show the model

Show the person each model you create or change as soon as its first run succeeds, and any model or file they ask to see. A board is shown as its STEP: cad pcb step FILE opens it as a cad model, and so does the design script's importStep model. Its page is the view: line of the run, or the url that cad viewer --json FILE prints (never guess the port). Show it with the first of these you have:

  1. cad_show among your tools (your host may prefix it): call it with the model's id or the

    file's absolute path.

  2. A tool that opens a page in the app's own browser pane (not the person's own browser): open

    the page there, and give the person the link as well.

  3. Neither: give the person the link, to open in their browser.

Fabrication files are downloads: give their paths. To check your own work, use cad model snapshot on the board's model, never a screenshot of the page.

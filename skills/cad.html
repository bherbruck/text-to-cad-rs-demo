#CAD modeling and inspection

Designs and edits 3D CAD - parametric parts, assemblies and 2D cut profiles, written as TypeScript with @cad/sdk and shown live in the cad viewer. Use for any request to model, change, measure, inspect, export or convert a part or a CAD file (STEP, STL, 3MF, GLB, OBJ, DXF), for references copied from the viewer, and to check whether a part can be machined, cut and bent, molded or printed.

A model is a TypeScript function that returns a shape built with @cad/sdk. Shapes are lazy: the script only describes an op graph, and running it builds that graph in the cad server, which holds the result as a document. The page the person has open follows every run, and every command (inspect, snapshot, export, interference) acts on that document by its id. Files are exports, written when asked.

#Setup

Before first use in a chat, run cad --version. If cad is missing, tell the person to install text-to-cad-rs; nothing here works without it.

In a folder with no package.json, cad init writes one with tsconfig.json, src/example.ts and the SDK linked at node_modules/@cad/sdk. In an existing project, cad run links the SDK itself if it is missing. Never npm install @cad/sdk: the SDK ships inside cad, matched to its server.

Every command goes through one local server. cad run starts it when needed; cad server start | status | stop manage it. cad <command> --help is the complete, current interface. Paths are relative to the working directory.

#Write a model and run it

src/bracket.ts:

import { box, cylinder, model, param } from "@cad/sdk";

function bracketBody(width: number, thickness: number, bore: number) {
  return box(width, 20, thickness)
    .cut(cylinder(bore / 2, thickness * 2))      // a tool longer than what it cuts
    .fillet("|Z", 2)
    .label("bracket", { color: "#4a6fa5", material: "aluminum" });
}

export const bracket = model("bracket", () => bracketBody(param("width", 40, { min: 20, max: 80, unit: "mm" }), 6, 8));
export const bracketWide = model("bracket_wide", () => bracketBody(60, 6, 8));

if (import.meta.main) {
  await bracket();
  await bracketWide();
}
cad run src/bracket.ts

  parts 1 · bounds 40 × 20 × 6 mm · volume 4498.4 mm³ · mass 12.1 g
  id: 0dc50a92-a21f-5895-a245-ebdeb5352f3b
  view: http://127.0.0.1:7878/view/0dc50a92-a21f-5895-a245-ebdeb5352f3b?token=…

Each model call prints how it built, what it holds, its document's id: and its page, view:. The id comes from the script's path and the model's name, so it is the same on every run: use it for every command, and give the person the page once (Show the model).

  • A model function takes no arguments. Dimensions are arguments of a plain helper, and each

    configuration is a model(...) of its own. await m() returns a handle: .id, .url, .result, .inspect(), .export(), .snapshot(), .interference().

  • Running the script is the rebuild, and it writes no file. The server caches every op by its

    inputs, so after an edit only what changed is recomputed (hits / misses on the first line). Keep the calls under if (import.meta.main) so other scripts can import the models.

  • Every call returns a new shape; nothing is modified in place. a.cut(b) leaves a as it

    was, so const body = a.cut(b), not a.cut(b); return a.

  • Nothing is measured in the script. A shape has no bounding box or volume until the server

    builds it: read numbers from the run's summary, cad model inspect, or the handle after the build (inspection).

  • Labels name parts in every reference, check and export; label after the last boolean or

    feature, since those return plain shapes. Colours are "#rrggbb"; a material is a preset name ("aluminum", "pla", …) or { name, density } in g/cm³ and gives the part a mass.

  • Assemblies are assembly("label", [parts…]) of labelled parts, each placed with

    .translate / .rotate. Helpers that return parts are shared between the part's own model and the assembly's (assemblies).

  • Units are millimetres and degrees, +Z up. Errors print error: … with at file.ts:line, and

    the run exits 1.

#Commands

Each acts on the document as the last run left it. $ID is a model's id.

CommandGives
cad model list [--json]Every document: id, model, parts, updated, script
cad model inspect "$ID" ["$ID#<ref>"] [--json]Parts, bounds, volume, mass, parameters; with a ref (the id, #, then a part path and optionally /face n or /edge n), that part, face or edge as JSON with made_by: the ops and source lines that made it
cad model snapshot "$ID" out.pngA picture: --camera top (or x,y,z), --display hidden-line, --part base, --size 1600x1200
cad model export "$ID" a.step b.stl c.dxfFiles, by suffix; nothing rebuilds (exports)
cad model interference "$ID"Every pair of parts that shares volume (no interference otherwise); exit 1 if any
cad model dfm "$ID" --process ...A manufacturing check (Can it be made?)
cad model bom "$ID" [--json]The bill of materials: parts by designation and material, with counts (standard parts)
cad viewer FILE… [--json]Opens STEP/STL files as documents and prints their pages (--json: [{ file, id, url }])
cad model export "$ID" out/bracket.step out/bracket.glb
cad model export "$ID" out/bracket.stl out/bracket.3mf --tolerance 0.02

A reference such as 0dc50a92-…#bracket/face 7 is what the viewer copies when the person picks something: a document, a part by its path of labels, then a face or edge (numbered from 0). Resolve it with cad model inspect "$ID" '<reference>' (the whole reference as copied, or just the part after #), then edit the line its made_by names.

--tolerance and --angle apply to mesh files only (.stl .3mf .glb .obj); an export that also names a STEP, BREP or DXF with them is refused: export those separately.

#Check each change

Read each run's output first: a part count, bounds or volume that contradicts the intent is the first thing to fix. Then check the change the way it can be checked:

The changeCheck it with
A number the person gave (a size, a distance, a volume)The summary's bounds and volume, or cad model inspect "$ID"
A number the design implies (a wall, a clearance, a mass)cad model inspect on the face or edge that has it, or a check on the handle after the build (inspection)
An assembly's partscad model interference "$ID"
Shape, placement, colourThe snapshots it takes to judge it, from more than one side
A 2D profile or DXFThe export, then a --camera top snapshot of the profile's model
A part made by a named processIts manufacturing check (below)
  • A snapshot shows arrangement and appearance; a number comes from the geometry, never from a

    picture.

  • A selector that matched nothing, or more than intended, is the usual cause of a failed or

    wrong fillet: inspect the edges by index (the viewer shows them) before guessing again.

  • Review an assembly from the inside out: a part alone (--part), then the whole, from behind as

    well as the front.

  • Say what a check cannot see beside what it passed.
  • Dropping or shrinking a feature the person specified to get a build through is a different

    design: say so instead.

  • A missing or conflicting dimension that changes the result is the person's to settle; a value

    chosen in its place is an assumption to report.

#Can it be made?

cad model dfm says whether a part can be made by a process and what to change where it cannot. Run it when the request names or implies a process (machined, sheet metal or laser cut, injection molded, 3D printed, or a printer, resin or filament named), or the person asks. A material alone names no process, but a thickness with a metal ("2 mm steel") is sheet. With none, build what was asked: no check, and no draft, reliefs or tool radii added.

ProcessCheckReference
CNC milling--process cnc (--material, --axes, --tools)CNC
Sheet cutting and bending--process sheet (--material, --thickness)Sheet metal
Injection molding--process molding (--pull, --material)Injection molding
3D printing--process printing --technology T (--build-volume, --nozzle, --layer-height, --angle-limit)3D printing
cad model dfm "$ID" --process cnc --material aluminum --tools 3,6,10

A named process is part of the design, not a review at the end:

  1. Read the process reference's Design it before modelling, and build its limits in.
  2. Give the part its material (.material("aluminum")): the check reads it, so every later check is

    the same one. Keep the shop's flags in a comment at the top of the script (// Check: cad model dfm "$ID" --process cnc --tools 3,6,10).

  3. Run that check after every run. The last line and the exit status are the result: OK (0,

    though warnings may remain), FAILED (1: the part cannot be made as drawn), NOT CHECKED (3: something was not judged, never a pass) and 2 for a refused command. Fix errors from each finding's refs, value and limit (--json); fix a warning when that leaves the request intact, else report it.

  4. In the hand-off, say the process, the material the check judged with, the findings left, and

    that the rules are general practice from published guides rather than a shop's own limits.

The result in full, a shop's own limits and a review are in manufacturing review.

#Show the model

Show the person each model you create or change as soon as its first run succeeds, and any model or file they ask to see. A model's page is the view: line its run prints, and a file's is the url that cad viewer --json FILE prints for it (never guess the port). Show it with the first of these you have:

  1. cad_show among your tools (your host may prefix it): call it with the model's id or the

    file's absolute path.

  2. A tool that opens a page in the app's own browser pane (not the person's own browser): open

    the page there, and give the person the link as well.

  3. Neither: give the person the link, to open in their browser.

The page follows every run of the model. A file you export is a download: give its path. Showing is for the person: to check your own work, use cad model snapshot, never a screenshot of the page.

#Hand off

Say what was made or changed, the files written, the checks run and what they showed, what no check covered, and every assumption or departure from the request.

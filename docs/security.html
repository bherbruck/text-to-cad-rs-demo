#Security and resource limits

cad runs a local server for one user. It builds models from scripts the user runs, opens files the user names, and writes files the user asks for. This page lists what the server defends against, how, and what it leaves to the operating system.

#Threat model

Trusted: the person at the keyboard. They run cad, hold the token, and every path they name is a file they mean to read or write. Writing an export to /home/me/out.step is the feature.

Untrusted:

  1. Web pages in the user's browser. Any site can make the browser send requests to

    127.0.0.1. It must not be able to read documents, trigger builds, or write files.

  2. Other local users on a shared machine. They must not learn the token or read saved

    documents.

  3. Model scripts and files from elsewhere: a downloaded .ts, STEP or STL file, or an IR

    envelope. They must not crash the server, exhaust its memory or CPU without bound, or make it read or write files the user did not name.

  4. Clients that misbehave: huge bodies, many requests, disconnecting mid-build.

Not in scope: an attacker who already runs code as the user (they can read ~/.cad and /proc), bugs inside OCCT, gmsh or CalculiX on hostile input beyond what their own parsers reject, and network exposure. The server binds to loopback only and refuses to listen elsewhere.

#Web pages: token, Host and Origin

  • Token. Every /api route except /api/health needs the 128-bit random token, as

    Authorization: Bearer … or ?token= (the viewer page and its WebSocket). It is compared in constant time (ct_eq), so response timing reveals nothing about the right value. A page on another origin cannot read the token: it is only in ~/.cad/server.json (0600) and the URLs cad prints.

  • Host gate. Requests whose Host is not 127.0.0.1:PORT, localhost:PORT or

    [::1]:PORT are refused with 403. This stops DNS rebinding, where evil.example re-resolves to 127.0.0.1 to read responses as same-origin.

  • Origin gate. A request carrying an Origin header (every cross-site browser request and

    every WebSocket upgrade) is refused unless that origin is a page on this machine (127.0.0.1, localhost or [::1], any port, so the viewer's dev server works). A foreign page cannot make the server act, even with a guessed or leaked token.

  • WebSocket (/api/events): behind the token, the Host gate and the Origin gate. It only

    sends events (document id and version), never reads client data.

#Files

  • Paths in requests (export files, snapshot out, /api/open path) must be absolute,

    at most 4096 bytes, with no NUL or line breaks. They name files the token holder chose.

  • Writes are atomic: written to a temporary file in the same folder, then renamed over the

    target. A symlink at the target is replaced, not written through. A failed write leaves the old file and no temporary file behind.

  • /api/open reads only STEP and STL (by suffix), at most 512 MB. The size is checked from

    the file's metadata before it is read. The response is the parsed document (parts, bounds), never the file's bytes. A file that does not parse is an error that does not echo its contents.

  • Static routes: the embedded viewer is served by exact name. /wasm/NAME accepts only plain

    file names ([A-Za-z0-9._-], not starting with a dot), so there is no traversal.

  • ~/.cad (or $CAD_HOME) is created 0700. server.json (the token), server.log (which

    prints the viewer URL with the token) and the saved documents in docs/ are created 0600. An existing folder is tightened to 0700 on start.

  • Saved documents (docs/<id>.cad) are read back only if the id is a UUID, the kernel

    matches, and the container parses. Every length field is bounds-checked; anything else is deleted with a log line.

#Cancellation

A build carries a cad_kernel::Cancel. It is set when:

  • the build runs past its deadline;
  • a newer build of the same document starts (the older one stops and records nothing;

    its client gets {"ok": false, "superseded": true});

  • the client disconnects (axum drops the handler, and its guard sets the flag).

The engine checks the flag between operations. OCCT also stops inside long ones (booleans, splits, meshing, STEP import) through its own CancelFlag, which the adapter trips from the Cancel's hook. Builds run on the blocking thread pool, so a long build never holds up the viewer's GETs, the WebSocket, or a build of another document. The tests check this (crates/cad/tests/hardening.rs).

#Parsers, fuzzed

crates/cad-engine/tests/fuzz.rs drives every parser and writer the engine owns with a fixed-seed xorshift generator (CAD_FUZZ_ROUNDS=10 for a longer run). Nothing may panic or recurse without bound, and the same input always gives the same answer:

  • IR JSON (mutated envelopes; 100 000-deep nesting), and random graphs of real ops built on OCCT

    with their mesh, snapshot and drawing;

  • the reference grammar (random strings; every label round-trips through format_ref);
  • STL, binary and ASCII (including a header that claims 4 billion triangles);
  • mesh.bin, GLB and saved-document containers (mangled headers and length fields, every

    truncation);

  • STEP canonicalisation (mutated files; a 200 000-deep chain of references), which is

    iterative and does not exhaust the stack;

  • the SVG, PDF and 3MF writers with every awkward character, including XML-illegal control

    characters, which are dropped. Each output is parsed back as XML.

Fixes the review made:

  • length arithmetic that could overflow on 32-bit (wasm) targets: STL, mesh.bin, saved

    documents, GLB;

  • a GLB reader that sliced past its end;
  • recursive STEP hashing;
  • control characters in SVG and 3MF XML.

#Owned elsewhere

  • SDK selector strings are parsed in TypeScript (packages/sdk); the engine only sees the

    JSON selector, which serde bounds.

  • URDF, SRDF and MJCF readers (crates/cad-robot, roxmltree, which resolves no external

    entities): done. crates/cad-robot/tests/fuzz.rs checks ~3,800 fixed-seed mutants under catch_unwind (no panics; the same bytes give the same report), and a file over 64 MB (check::MAX_FILE) is refused before it is read. An MJCF <include> loop stops at depth 8.

  • Long tools (interference, ranges, DFM, render): done at the server. Each runs under a

    cad_kernel::Cancel (with_cancel), stopped past CAD_TASK_TIMEOUT seconds (600) or when the client goes away, and answers 503 "<tool> stopped: …" rather than a result from interrupted steps (crates/cad/tests/mechanisms.rs::long_tools_stop_at_the_task_deadline). Render stops mid-image through its progress callback.

  • Loop-level stops: kinematics::ranges checks the flag before every sample and bisection

    step, interference before each part pair, and cad-fea's runner kills gmsh and ccx (engine); cad model fea runs through the same tool() deadline. cad-dfm checks the flag every 256 ray samples and between parts and processes, and refuses with "dfm stopped: …" rather than reading a cancelled kernel call as a measurement (crates/cad-dfm/tests/cancel.rs).

  • 3MF import does not exist: we only write 3MF, so there is no zip-bomb surface.

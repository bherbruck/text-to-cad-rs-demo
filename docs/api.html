#Server API (cad server)

One local server per user holds every document and serves the viewer. State file: ~/.cad/server.json → { "port": 7878, "token": "…", "pid": 123, "kernel": "occt" }.

Every /api request carries the token: Authorization: Bearer <token> or ?token=<token>. The viewer page is opened as http://127.0.0.1:<port>/view/<id>?token=<token> and keeps the token for its API and WebSocket calls. JSON everywhere unless noted.

#Documents

A document is one model's latest build. Its id is a UUIDv5 of abs script path + "::" + model (namespace 6ba7b811-9dad-11d1-80b4-00c04fd430c8, the URL namespace), so it is stable across runs. Files opened with cad viewer FILE get a UUIDv5 of the absolute file path.

type Doc = {
  id: string; model: string; script: string | null; file: string | null;
  kernel: string; version: number;           // bumps on every build, failed ones too (geometry stays from the last success)
  updatedAt: string;                          // ISO time
  params: Param[];
  bounds: Bounds | null;
  parts: PartInfo[];
  error: BuildError | null;                   // last build's error; geometry stays from the last success
  url: string;                                // viewer page
  joints: JointInfo[];                        // [] when the model is no mechanism (docs/ir.md "Joints")
  poses: { [pose: string]: { [joint: string]: number } };
  animations: Animation[];                    // docs/ir.md "Animations", resolved (below)
};
type Bounds = { min: [n,n,n]; max: [n,n,n] };
type PartInfo = {
  path: string;           // labels from the root joined by "/", e.g. "gripper/finger_left"; unique
  labels: string[];       // the same labels, unjoined (a label may itself contain "/"; quote it in refs)
  label: string; color: string | null;       // "#rrggbb"
  material: { name: string; density: number } | null;
  designation?: string;   // what it is bought as ("ISO 4762 M5x25"), from the part op; absent when unset
  kind: "solid" | "compound" | "shell" | "face" | "wire" | "edge" | "other";
  volume: number; area: number; mass: number | null;  // mass in g when material set
  center: [n,n,n]; bounds: Bounds; faces: number; edges: number; valid: boolean;
  src: string | null;     // where the part node was made
};
type Param = { name: string; value: number; min?: number; max?: number; step?: number; unit?: string; description?: string };
type BuildError = { message: string; op?: string; src?: string };

#Mesh payload

Typed arrays are base64 of little-endian data.

type MeshPayload = {
  id: string; version: number;
  parts: {
    path: string; label: string; color: string | null;
    positions: string;          // f32 xyz
    normals: string;            // f32 xyz
    indices: string;            // u32
    faceRanges: [number, number][];   // per face: [firstIndex, indexCount] into indices (face i = kernel face i)
    edgePositions: string;      // f32 xyz, line-list pairs (2 points per segment)
    edgeRanges: [number, number][];   // per edge: [firstVertex, vertexCount] into edgePositions
    faceFingerprints: string[];       // per face: its fingerprint ("References"), for refs that survive rebuilds
    edgeFingerprints: string[];       // per edge
  }[];
};

#Binary mesh

/api/docs/:id/mesh.bin is the same mesh as MeshPayload without base64: about a quarter smaller, and its buffers are viewed in place (new Float32Array(buf, 16 + jsonLength + offset, count)).

bytes 0..8    "CADMESH1"
bytes 8..12   u32 LE jsonLength (a multiple of 4)
bytes 12..16  u32 0 (reserved)
16..16+jsonLength   JSON header, padded with spaces
then          the data section: little-endian f32/u32 buffers, each 4-byte aligned
type Buf = { offset: number; count: number };   // offset in bytes into the data section; count in scalars
type MeshBinHeader = {
  id: string; version: number;
  parts: {
    path: string; label: string; color: string | null;
    positions: Buf;          // f32 xyz
    normals: Buf | null;     // f32 xyz; null with ?normals=0 (compute them from the triangles)
    indices: Buf;            // u32
    faceRanges: [number, number][];  // as in MeshPayload
    edgePositions: Buf;      // f32 xyz line-list pairs
    edgeRanges: [number, number][];  // as in MeshPayload; a seam edge has count 0
  }[];
};

The engine's cad_engine::mesh_binary writes it, and read_mesh_binary splits it again.

#Drawings

Exporting to .pdf or .svg writes an engineering drawing (one A-size sheet): orthographic views in third-angle (default) or first-angle projection plus an isometric, hidden lines dashed, centre marks on circular edges, hole callouts (4× Ø6 THRU, Ø4 × 5 DEEP, grouped by size and axis), overall dimensions (each model axis once), numbered notes and a title block (title, part number, material, scale, units, date, revision, projection symbol). The scale is the largest ISO 5455 scale (50:1 … 1:2000) at which the views fit; a requested scale that does not fit is refused with one that does. The bytes depend only on the content (no creation date).

type DrawingOptions = {
  sheet?: "A4" | "A3" | "A2" | "A1" | "A0";       // landscape; default A3
  projection?: "third" | "first";                  // default third
  views?: ("front" | "top" | "right" | "left" | "bottom" | "back" | "iso")[];  // default top, front, right, iso
  scale?: number;                                  // 0.5 = 1:2; default: largest standard scale that fits
  title?: string; partNumber?: string; material?: string; revision?: string; author?: string;
  date?: string;                                   // printed as given (the CLI passes today's date)
  notes?: string[]; generalTolerance?: string;     // e.g. "ISO 2768-m" → note 1
  hidden?: boolean;                                // hidden lines, default true
  dimensions?: boolean;                            // dimensions and hole callouts, default true
  part?: string;                                   // one part (or sub-assembly) by path
};

#FEA (stress checks)

POST /api/docs/:id/fea solves a linear static study (crate cad-fea: STEP via the engine → gmsh quadratic tets, touching parts bonded into one conformal mesh → CalculiX). Body: a Study (the same JSON cad model fea --study takes); returns FeaResult. The server keeps the latest result per document (dropped when the document is rebuilt). GET /api/docs/:id/fea returns { version, result: FeaResult, vonMises: FieldPayload, displacement: FieldPayload } for the viewer's colour overlay, or 404 when none has run since the last build. A POST with no fixtures and no loads returns { faces: [{ ref, surface, area, center, hint }] } (the faces to choose from) and solves nothing. Studies run one at a time. A finished study sends { "type": "fea", "id", "version" } on /api/events. A part with no bonded path to a fixture is refused (not_connected: ..., with the nearest gap).

type Study = {
  fixtures: { faces: string[]; type?: "fixed" | "roller" }[];        // refs: "part/face n" or viewer refs
  loads: ({ type: "force"; faces: string[]; vector_N: [n, n, n] }
         | { type: "pressure"; faces: string[]; pressure_MPa: number }   // positive into the part
         | { type: "gravity" | "acceleration"; vector_g: [n, n, n] })[];
  material?: string | Material;            // every part: a table name ("aluminium 6061", "steel", "PETG"…) or numbers
  parts?: Record<string, string | Material>;   // one part's, by path
  mesh?: { size_mm?: number; refine?: boolean };  // default: bbox diagonal / 40; refine when SF < 3
  margin?: number;                          // safety factor to keep, default 2
  checks?: ({ kind: "stress" } | { kind: "displacement"; limit_mm: number; faces?: string[]; label?: string })[];
};
type Material = { name?: string; E_MPa: number; nu: number; yield_MPa: number; density_t_per_mm3?: number };
type FeaResult = {
  ok: boolean; summary: string;
  findings: { severity: "error" | "warning"; code: string; message: string; at_mm?: [n, n, n]; face?: string }[];
  measurements: {
    max_von_mises_mpa: number; max_von_mises_at_mm: [n, n, n]; max_von_mises_face: string | null;
    max_von_mises_gauss_mpa: number; yield_mpa: number; safety_factor: number; weakest_part: string;
    max_displacement_mm: number; max_displacement_at_mm: [n, n, n]; max_displacement_face: string | null;
    applied_force_n: [n, n, n]; reaction_force_n: [n, n, n];
    mesh: { size_mm: number; elements: number; nodes: number; dofs: number };
    refined: { from_size_mm: number; from_max_von_mises_mpa: number; size_mm: number; max_von_mises_mpa: number } | null;
    parts: { path: string; material: Material; peak_mpa: number; peak_gauss_mpa: number; peak_at_mm: [n, n, n];
             peak_face: string | null; safety_factor: number; max_displacement_mm: number }[];
    checks: { kind: string; label: string; value: number; limit: number; unit: string; ratio: number; status: "passes" | "close" | "fails" }[];
    contacts: { a: string; b: string; type: "bonded" | "not_connected"; area_mm2: number; gap_mm: number }[];  // part pairs touching or within 1 mm
    seconds: number;
  };
};
type FieldPayload = { label: string; unit: string; min: number; max: number;
  parts: { path: string; values: string;    // base64 f32 LE, one per vertex of that part's MeshPayload positions
           vectors?: string }[] };          // displacement only: base64 f32 LE xyz per vertex (mm); draw position + scale·vector for the deformed shape

Units are fixed: mm, N, MPa, t/mm³, g. Material defaults to each part's model material looked up in the table (its density from the model); a part with neither is refused by name. Errors (yields, displacement_over_limit) make ok false; warnings (low_margin, peak_at_fixture, peak_concentration, mesh_not_converged, large_displacement, reaction_mismatch) do not. Snapshots take an optional field: POST /api/docs/:id/snapshot with "field": "vonMises" | "displacement" colours the faces by the latest result (blue → red, 0 → peak).

#Persistence

Documents survive a server restart: each successful build or open writes $CAD_HOME/docs/<id>.cad (the geometry, kernel-native) and <id>.json (version, updatedAt, error, model, script/file, kernel), atomically. On start the server loads them; files from another kernel, or that fail to load, are deleted. DELETE /api/docs/:id removes them.

#References

What the viewer copies when the person picks something, and what inspect resolves:

  • <id> — the document
  • <id>#<part path> — a part
  • <id>#<part path>/face <n> — a face (0-based index, kernel order)
  • <id>#<part path>/edge <n> — an edge

Grammar (shared fixture: tests/fixtures/refs.json, read by the Rust and the viewer tests):

  • Face and edge numbers are 0-based, in kernel order (the same order as faceRanges/edgeRanges).
  • A part path is labels joined by /. A label containing /, #, ,, " or \, or with

    leading/trailing whitespace, is written in double quotes with \" and \\ escaped: <id>#"a/b"/face 2, <id>#arm/"link, left"/edge 0.

  • Duplicate sibling labels are made unique when the document is built: link, link_2, link_3.
  • The element suffix is /face N or /edge N with exactly one space; parsing accepts any

    whitespace and is case-insensitive for face/edge.

  • When a part path is a prefix of another (arm and arm/link), the longest match wins.
  • Fingerprints make a face or edge ref survive rebuilds: <id>#bracket/face 7~0k3m9a2x4b1.

    The 11 characters after ~ (0-9a-z without i l o u, case-insensitive on input) encode what the face or edge looked like, relative to its part's bounding box: its surface or curve type, its direction (a plane's normal; an axis, sign-free), where its centre sits in the box, and its area or length against the box's diagonal. Copy refs with them: MeshPayload (and mesh.bin) carry faceFingerprints / edgeFingerprints per part, index for index, and inspect returns stable_ref.

  • Resolving a fingerprinted ref:
    • The index still matching its fingerprint is the answer.
    • Otherwise every face (edge) of the part is scored against the fingerprint. The best one is

      used when it scores at least 75 % and leads the runner-up by 8 points; inspect then adds resolved: { index, moved_from, confidence }.

    • A ref that matches nothing ("no longer exists… pick it again"), matches only poorly, or

      matches two faces nearly equally ("ambiguous now: face 3 (90 %) and face 9 (88 %)") is refused, naming the candidates. It is never silently re-pointed.

    • Refs without a fingerprint resolve by index, as before.

Inspect without a ref returns the Doc. With a ref it returns { ref, part: PartInfo, face?: FaceInfo, edge?: EdgeInfo, made_by: { op, src }[] } where made_by lists the ops in the part's history, newest first, with their source lines.

#Snapshot

camera: iso (default), front, back, left, right, top, bottom, or [x,y,z] view direction toward the camera. display: shaded (default, with edges), wireframe, hidden-line. Rendered in Rust by a software rasteriser; default 1024×768.

#Mechanisms

A model's joints and poses (docs/ir.md "Joints") come back resolved to part paths:

type JointInfo = {
  name: string;                     // unique in the document
  type: "revolute" | "prismatic" | "fixed";
  unit: "deg" | "mm" | null;
  parent: string; child: string;    // paths (a part's, or an assembly's)
  axis: { origin: V3; dir: V3 } | null;   // document coordinates as built; dir unit length
  limits: { min: number; max: number } | null;
  default: number;                  // as-built value
  moves: string[];                  // every part path it moves (its child and all that rides on it)
  after: string | null;             // the joint it rides on (moves this joint's axis), if any
  group: string | null;             // the cylindrical/ball joint this is a degree of freedom of
  follows: { joint: string; ratio: number; offset: number } | null;  // coupled: value = offset + ratio * value(joint)
};
type Pose = string;                 // a pose's name, or JSON joint values: '{"lid": 45}' (the rest as built)

Doc.joints are in chain order: every joint after the one it rides on.

Posing (forward kinematics, what the viewer does client-side): with values[j] each joint's value (its default where not set; a joint with follows set to offset + ratio * values[leader], leaders first), give each joint a matrix in chain order, M[j] = M[after(j)] · L_j(values[j] - default_j) (M[null] = I), where L is the rotation by that many degrees about axis (right-handed about dir, through origin) or the translation by that many mm along dir. A part's placement is M of the last joint in chain order whose moves holds it (identity if none). Applied to the as-built mesh, that is the posed part. Values outside limits are refused everywhere a pose is accepted.

pose on snapshot and interference poses the document first; an unknown pose or joint, a fixed joint given a value or a value out of limits is a 400 naming it.

#Ranges

Joint stops found from the geometry: each revolute or prismatic joint is moved alone from as built (the others as built) step (degrees or mm) at a time each way, a full turn for a revolute and the document's extent for a slide, until a part it moves meets a part of the link that holds it; the meeting is then bisected between samples. Nothing is changed: write the stops into the joint's limits.

  • Meets: parts apart as built meet where their surfaces come within clearance. Parts within

    clearance as built (a lid on its box, a carriage on its rail, a pin in its bore) are resting: they meet only where their shared volume grows by over 0.1 mm³ (one pushed into the other), never by sliding along each other.

  • Near a turn's axis a millimetre is a wide angle: on a revolute, a gap within clearance counts

    only where the parts would touch within 5.73° more turning (a gap under a tenth of its distance from the axis), so a lid or a door hinged on its edge stops near flat, not where its edge first comes near. When several parts meet at one sample, the deepest names the stop.

  • Stop vs clash: a stop is the moving parts meeting the parent's link (the parts moved by exactly

    the joints that move the parent); meeting any other part first is a clash of this pose, reported beside the stop and not a limit.

type Ranges = { clearance: number; step: number; joints: JointRange[]; warnings: string[] };
type JointRange = {
  joint: string; type: "revolute" | "prismatic"; unit: "deg" | "mm";
  asBuilt: number;
  lower: number | null; upper: number | null;   // offsets from as built: the last clear sample each way
  range: [number, number] | null;               // asBuilt + [lower, upper], the joint's own values
  lowerContact: Contact | null; upperContact: Contact | null;   // what stopped it
  lowerClash: Contact | null; upperClash: Contact | null;       // met first, not the parent's link
  resting: [string, string][];                  // (moving, still) pairs within clearance as built
  why: string;                                  // "" with both stops, else e.g. "clear all the way round"
};
type Contact = { moving: string; still: string; at: number /* bisected offset */; gap: number | null; overlap: number | null };

A document with no joints is a 400 no_joints: …. step is 0.05 to 30, clearance 0 to 50 mm.

#Animations

Doc.animations are the IR's animations resolved: names unique in the document (<assembly path>:<name> where two assemblies share one), parts as part paths, pose keys as joint values by document joint name, about filled in.

type Animation = { name: string; duration: number; loop: boolean; tracks: Track[] };
type Track =
  | { kind: "pose"; keys: { t: number; value: { [joint]: number } }[]; interpolation: Interp }
  | { kind: "translate"; parts: string[]; keys: { t: number; value: V3 }[]; interpolation: Interp }
  | { kind: "rotate"; parts: string[]; axis: V3 /* unit */; about: V3; keys: { t: number; value: number }[]; interpolation: Interp }
  | { kind: "scale"; parts: string[]; about: V3; keys: { t: number; value: number }[]; interpolation: Interp };
type Interp = "cubic" | "linear" | "step";

Sampling at t (clamped to 0 .. duration), what a player does:

  1. Find the segment: keys i, i+1 with t_i <= t < t_{i+1}; s = (t - t_i) / (t_{i+1} - t_i), eased

    to 3s² - 2s³ (cubic), kept (linear) or 0 (step). At or past the last key: the last key's value. Before the first key: a pose track takes its first key; a part track does nothing (identity).

  2. Pose track: each joint a + s (b - a) between the keys' full values (joints a key leaves out at

    their default), followers from their leaders; each part's M_pose by forward kinematics above.

  3. Part tracks: translation offsets add; a rotation is by the interpolated degrees about axis through

    about; a scale about about. Kinds compose in track order.

  4. A part's placement: T(Σ offsets) · Rot · Sc · M_pose.

The engine gives the same matrices (animation_matrices, wasm animationMatrices(id, name, t)), and every GLB export carries each animation as a glTF clip of that name (nodes named by part path; three.js sanitises / out of node names), with extras: { loop, duration }.

#Render

Photoreal pictures for people (crates/cad-render): a CPU path tracer over the parts' tessellations, in Rust, natively on every core and in the browser engine single-threaded. Geometry is checked with a snapshot, never a render. POST /api/docs/:id/render (CLI cad model render, MCP cad_render, wasm render/renderTurntable) takes RenderOptions, every field optional:

type RenderOptions = {
  preset?: "draft" | "final";      // draft: 800×600, 16 samples, 3 bounces; final: 1600×1200, 256, 6
  camera?: "iso" | "front" | "back" | "left" | "right" | "top" | "bottom" | [x, y, z];   // toward the camera
  lens?: number;                   // mm on a 36 mm sensor (50)
  fit?: number;                    // 1: the bounding box's corners touch the frame (1.15)
  fstop?: number;                  // depth of field, focused on the model's centre; scene units are mm: small parts blur a lot
  width?: number; height?: number; // height defaults to 3/4 of width
  samples?: number; bounces?: number;
  environment?: "studio" | "sky" | "white" | "dark";   // lights sit relative to the camera's heading
  intensity?: number; exposure?: number;               // light multiplier; stops
  ground?: "shadow" | "plane" | "none";                // shadow: a shadow catcher; plane: a visible floor
  groundColor?: string;                                // "#rrggbb" of the floor
  background?: "environment" | "transparent" | "white" | "black" | string;   // "#rrggbb"
  pose?: string;                   // a pose name or JSON joint values
  animation?: string; time?: number;   // the model `time` seconds into an animation (not with pose)
  denoise?: boolean;               // edge-aware à-trous (on)
  part?: string;                   // only this part or the parts under this path
  seed?: number;                   // the same options give the same image
};
type Turntable = { frames?: 24; degrees?: 360; fps?: 12; animate?: boolean };  // animate: play `animation` over the turn
  • Materials come from each part's material and colour: aluminium, steel, stainless, titanium, brass,

    bronze, copper, gold and chrome are metals (a colour tints them: anodised); PLA, PETG, ABS, nylon, PC… are plastics; rubber/TPU matte; oak/pine/plywood wood-toned; glass (and uncoloured acrylic/PC) refracts. No material: a plastic in the part's colour.

  • Out: PNG RGBA (straight alpha; with a transparent background the ground shadow lives in alpha), a

    looping GIF for a turntable, or one PNG per frame.

  • A render is deterministic: one seed, one image, whatever the thread count.

The request body is RenderOptions plus out (an absolute path) and turntable. Without out the reply carries the image: { png } (base64), or { gif } for a turntable. With out: a .png (or .gif for a turntable), or for a turntable a folder (frame_000.png…) or a name with %0Nd (spin_%03d.png). The reply always has { written, width, height, samples, frames, seconds }. camera also takes "AZ:EL" as snapshots do. A bad option is a 400 naming it.

#Circuit boards

POST /api/pcb/{op} runs cad pcb (crates/cad-pcb; KiCad's kicad-cli for all but inspect): inspect {file}, erc {file}, drc {file, parity?, refill?}, export {file, kinds, out?} (kinds: gerbers, drill, pos, bom, pdf, sch-pdf, svg, step, netlist), step {file, out?}, write {design, dir, fill?}, route {file, out?, options?} (the router's settings, e.g. {"width": 0.25, "nets": ["SDA"]}). Paths are absolute. The reply is the command's JSON plus exit (0 done, 1 ERC/DRC errors); a file or KiCad that cannot be read or run is a 400. A board's STEP opens as a document (POST /api/open), which cad pcb step does for you.

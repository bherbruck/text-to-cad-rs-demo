#Workspace quality report

The checks: cargo clippy --all-targets per crate (all = "warn" from the workspace lints); missing_docs (cargo clippy -p X -- -W missing_docs) and cargo doc --no-deps warnings; Cargo dependencies that no source, test, example or build script names; #[allow] without a reason comment; and cargo fmt --check against the new root rustfmt.toml (edition 2024, max_width = 110). The vendored occt-* crates are out of scope. No clippy.toml is needed.

Each owner fixes their own crates. Others are still editing them, so nothing here has been changed. Counts are as of this report.

Every #[allow] carries its reason. cargo fmt --check is clean for the first three; in cad-engine only other owners' files differ (listed below). Changes:

  • clippy: indexed loop in Bounds::add_point; std::slice::from_ref; as_chunks for

    chunks_exact(N), including in cad-engine/tests/ported_mesh.rs.

    cad-kernel-occt.

  • The engine's own files are formatted.

#CI

Added to .github/workflows/ci.yml: a lint job that passes today. It runs clippy on the crates that are clean (now including cad-dfm) and fails on any warning in them, plus cargo fmt --check on the clean crates. It does not use -D warnings, because that would also deny the vendored occt-* crates, which are workspace members (occt-kernel-capi has 3 chunks_exact lints):

- run: |
    cargo clippy -p cad-kernel -p cad-kernel-occt -p cad-engine -p cad-fea --all-targets --message-format short 2>&1 | tee clippy.txt
    ! grep -E '^crates/(cad-kernel|cad-kernel-occt|cad-engine|cad-fea)/.*(warning|error)' clippy.txt
- run: cargo fmt --check -p cad-kernel -p cad-kernel-occt -p cad-fea

Status: every crate except the vendored occt-* is now in the lint job (clippy and fmt). Proposed next: add RUSTDOCFLAGS="-D warnings" cargo doc --no-deps for the same crates. Every owner reports it clean; check it on CI before making it required. cargo machete is not installed on this box; the unused-dependency check here was a script over each crate's Cargo.toml and sources.

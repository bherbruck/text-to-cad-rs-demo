#Model IR (TypeScript SDK → Rust engine)

A model script (TypeScript, run by cad run) builds a lazy op graph with @cad/sdk. Calling a model posts its graph to the server (POST /api/build), which evaluates it on the active kernel with a content-hash memo cache. The SDK computes no geometry; everything numeric about the result comes back from the server.

Units: millimetres, degrees. +Z up. Points/vectors are [x, y, z].

#Envelope

{
  "version": 1,
  "script": "/abs/path/src/bracket.ts",
  "model": "bracket",
  "params": [{ "name": "wall", "value": 2, "min": 1, "max": 5, "step": 0.5, "unit": "mm", "description": "" }],
  "nodes": [ { "op": "box", "args": { "size": [40, 20, 6] }, "in": [], "src": "src/bracket.ts:7" } ],
  "root": 0
}
  • nodes is topologically ordered; in holds indices of earlier nodes.
  • src is relative/path.ts:line of the user code that created the node (from the JS stack,

    skipping SDK frames). Used for made_by in inspection and in error messages.

  • The node hash is sha256(op, canonical args, input hashes); equal subgraphs are cached across

    runs and across models.

  • root must evaluate to a shape, part or assembly.

#Selector

Selects faces or edges of the input shape, evaluated by the engine on kernel-reported FaceInfo/EdgeInfo. The SDK also parses CadQuery-style strings into these: ">Z", "<X", "|Z", "#Z", "%LINE", "%CIRCLE", "%PLANE", "%CYLINDER", combined with and, or, not and parentheses, e.g. "|Z and >X".

{ "kind": "all" }
{ "kind": "index", "indices": [0, 3] }
{ "kind": "dir", "dir": V3, "mode": "max" | "min" | "parallel" | "perpendicular" }
{ "kind": "type", "type": "line" | "circle" | "ellipse" | "spline" | "plane" | "cylinder" | "cone" | "sphere" | "torus" }
{ "kind": "near", "point": V3, "count": 1 }
{ "kind": "inside", "min": V3, "max": V3 }
{ "kind": "radius", "min": r, "max": r }
{ "kind": "and", "of": [Selector…] }
{ "kind": "or", "of": [Selector…] }
{ "kind": "not", "of": Selector }

Semantics, with d the unit direction:

  • max/min: the items whose centre's projection on d is within 1e-4·size of the largest /

    smallest (any face or edge type, as CadQuery). >Z faces is a box's top face; >Z edges are its four top edges.

  • parallel (|): edges that are lines along d; faces that are planes with normal ±d.

    |Z edges are the vertical edges of a box.

  • perpendicular (#): edges that are lines ⟂ d; planar faces whose normal ⟂ d

    (#Z faces are a box's four sides).

  • Directions compare with a 1e-6 tolerance on the unit vectors' cross/dot products.

#Joints

An assembly that is a mechanism declares its joints and named poses in its own args. Its parts are built where they stand: the geometry is the mechanism at every joint's default (its as-built value). Nothing about a joint changes the built geometry or any export; posing is on demand (--pose, the viewer's sliders, cad model ranges).

{ "op": "assembly", "in": [3, 7], "args": {
    "label": "box",
    "joints": [
      { "name": "lid", "type": "revolute", "parent": "tray", "child": "lid",
        "axis": { "origin": [0, 30, 40], "dir": [-1, 0, 0] }, "limits": { "min": 0, "max": 110 } }
    ],
    "poses": { "closed": { "lid": 0 }, "open": { "lid": 100 } } } }
type Joint = {
  name: string;                               // unique within the assembly
  type: "revolute" | "prismatic" | "cylindrical" | "ball" | "fixed";
  parent: string;                             // what holds the joint: a child label of this assembly,
  child: string;                              //   or a "/" path into a sub-assembly ("arm/forearm");
                                              //   the child moves with everything below it
  axis?: { origin: V3; dir: V3 };             // required unless fixed; this assembly's coordinates as built
  limits?: { min: number; max: number };      // in the joint's values
  default?: number;                           // the value the geometry is drawn at (0)
  slideLimits?: { min: number; max: number }; // cylindrical: the slide's limits
  slideDefault?: number;                      // cylindrical: the slide's as-built value
  effort?: number;                            // revolute/prismatic: most torque N·mm / force N (robot descriptions)
  velocity?: number;                          // revolute/prismatic: top speed deg/s / mm/s (robot descriptions)
};
  • Values: a revolute turns its child by value - default degrees about axis, right-handed

    about dir; a prismatic slides it value - default mm along dir. A fixed joint takes no value: it fastens the child to the parent's link (it then moves with whatever moves the parent).

  • Multi-axis joints are posed by their degrees of freedom, each a single-axis joint of the

    document riding on the one before it: a cylindrical joint is <name>.turn (degrees, limits, default) and <name>.slide (mm, slideLimits, slideDefault) on one axis; a ball joint is <name>.x, <name>.y, <name>.z (degrees, each within limits, as built at 0), turns about axes through axis.origin: z is axis.dir, x a perpendicular to it (world X made perpendicular, or world Y when z is near X), y = z × x; x first, then y, then z, each about its axis as moved by the ones before. A joint name may not contain ..

  • Chains: a joint whose parent lies in another joint's child rides on it: posing moves the

    outer joint's child, its axis and everything on it. A part's placement is its chain of joints applied innermost first, each about its axis as built. Each part is placed by at most one joint of an assembly; a loop (a joint that would move its own parent) is refused.

  • Nested assemblies keep their own joints; an outer joint whose child is the sub-assembly

    moves its whole mechanism. transform on an assembly moves its axes too (a mirror reverses a revolute's dir so a positive value still turns the mirrored child the mirrored way; a scale scales prismatic values).

  • Names in the document are the declared names where unique, else

    <assembly path>:<name> (gripper/left:knuckle); pose names the same.

  • Poses name joint values (the joints a pose leaves out stay as built). A pose value or

    default outside the joint's limits, an unknown joint, a joint without an axis, two joints with one name and a reference to no part are refused when the model builds, by name.

#Couplings

Joints that move together (gears, a rack and pinion, a screw's turn and travel): a follower's value is always offset + ratio * leader, so posing the leader poses the follower.

type Coupling = {
  leader: string;      // a joint (or degree of freedom, `hub.turn`) of this assembly
  follower: string;
  ratio: number;       // follower units per leader unit: gears -r1/r2; rack mm per degree 2πr/360
  offset?: number;     // follower value at leader 0; default: both at their as-built values
};

A follower is never posed directly: a pose, an animation key or a --pose that sets it is refused, naming its leader. A leader whose value drives a follower outside the follower's limits is refused the same way. A joint follows at most one coupling; a leader may itself follow another (no loops). cad model ranges sweeps a leader with its followers riding along, and never a follower alone.

#Animations

An assembly's own clips, baked into every GLB the model exports as glTF animations (one per animation, LINEAR samplers of node translation, rotation and scale at 30 samples a second plus every key time): an explode, a reveal, a showcase, the mechanism driven through poses. They change nothing else (a snapshot, a STEP, --pose show the model as built).

type Animation = {
  name: string; duration: number /* s */; loop?: boolean;     // loop: kept in the GLB's extras
  keys?: PoseKey[];          // shorthand for one pose track: { kind: "pose", keys }
  tracks?: Track[];
};
type PoseKey = { t: number; pose?: string; values?: { [joint]: number } };   // one of pose / values
type Track =
  | { kind: "pose"; keys: PoseKey[]; interpolation?: Interp }                 // at most one per animation
  | { kind: "translate"; parts: string[]; keys: { t; value: V3 }[]; interpolation?: Interp }      // mm offset
  | { kind: "rotate"; parts: string[]; axis: V3; about?: V3; keys: { t; value: number }[]; interpolation?: Interp }  // degrees
  | { kind: "scale"; parts: string[]; about?: V3; keys: { t; value: number }[]; interpolation?: Interp };            // factor, 0 hides
type Interp = "cubic" /* default: eased in and out at every key, 3s²-2s³ */ | "linear" | "step";
  • parts are names relative to the assembly: a part's label or path (feet/foot_1), an assembly

    (all its parts), or a glob (feet/*, wheel?; * and ? stay within a / segment).

  • about defaults to the centre of the named parts' bounds as built.
  • Key times lie in 0 .. duration, in order. A part track does nothing before its first key and holds

    its last; a pose track holds its first key before it. Pose keys name a pose or give joint values (the rest as built), within limits, followers excluded; between keys each joint eases on its own.

  • A part's placement at t: the mechanism posed by the pose track, then its scales, rotations and

    translations (Tr · Rot · Sc · M_pose); several tracks of one kind on a part compose in track order (translations add).

  • Unknown parts, poses or joints, a value out of limits, times out of range or decreasing, two pose

    tracks, a nonpositive duration and two animations of one name are refused when the model builds. transform on the assembly moves offsets, axes and points with it.
